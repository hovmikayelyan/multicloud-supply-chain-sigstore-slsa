# Supply-chain security Q&A

1. **Extra controls for SLSA L3 (already: GH Actions + Cosign + Rekor + CycloneDX).** Provenance must be generated by an
   isolated, trusted builder the project's own steps cannot influence (SLSA GitHub generator reusable workflow), signing
   material must be inaccessible to user build steps, builds must be ephemeral/isolated (no cache poisoning across runs),
   and the verifier must check builder identity + source (`slsa-verifier`). Plus hardened source (branch protection, reviews)
   and pinned dependencies/actions.
2. **Outdated deps despite "we scan with Snyk".** The SBOM/scan is probably not of the shipped artifact: it was generated
   from the manifest/lockfile of the source repo or an earlier build rather than the final image (missing OS packages,
   vendored/transitive/bundled libs), is stale (generated once, not re-scanned as new CVEs are published), or the scan
   targets a different tag/digest than what runs in production.
3. **SBOMs only in a GitLab artifact repo.** Not sufficient. Artifacts expire, are not bound to the image digest, are not
   signed (can be altered) and are not discoverable from the registry/runtime. Attach the SBOM to the image as a signed
   in-toto attestation (OCI referrer) keyed by digest, and log it in a transparency log, so anyone holding the image can fetch
   and verify its SBOM.
4. **SBOM without signing is dangerous when** an attacker (or compromised pipeline/registry) can swap the SBOM: a
   backdoored image ships with a clean, forged SBOM, so vulnerability scanners and compliance gates trust it and approve
   a malicious artifact (and deployments tied to "has an SBOM" give false assurance).
5. **Enforce "only SLSA L3 builds in prod" across clouds.** AWS (EKS): Kyverno or OPA Gatekeeper admission policy verifying
   cosign signature + SLSA provenance attestation with the trusted builder identity (`slsa-github-generator` workflow);
   optionally AWS Signer + ECR. GCP (GKE): Binary Authorization with an attestor whose attestations are only created after
   `slsa-verifier` passes (plus Kyverno/Gatekeeper for keyless provenance checks). Back both with registry IAM so only the CI
   identity can push.
